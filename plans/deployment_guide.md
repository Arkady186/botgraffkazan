# Руководство по развертыванию проекта "Учёт граффити в Казани"

## Обзор архитектуры

Проект состоит из трёх основных компонентов:
1. **Веб-сайт (FastAPI)** – панель управления и публичная карта
2. **VK бот** – приём заявок из сообщества ВКонтакте
3. **Telegram бот** – приём заявок через Telegram

Все компоненты используют общую базу данных SQLite и хранилище медиафайлов.

## Почему GitHub Pages не подходит

GitHub Pages – это статический хостинг, который не поддерживает:
- Серверный код Python (FastAPI)
- Фоновые процессы (боты)
- Базы данных SQLite
- Обработку файловых загрузок

**Вывод:** Разместить весь проект на GitHub Pages невозможно без кардинальной переработки архитектуры.

## Рекомендуемые платформы для хостинга

### 1. Railway.app (рекомендуется)
- **Плюсы:** Простая настройка, интеграция с GitHub, бесплатный тариф, поддержка фоновых процессов (Worker), встроенные базы данных и хранилища.
- **Минусы:** Ограничения по ресурсам на бесплатном тарифе.

### 2. Render.com
- **Плюсы:** Аналогично Railway, бесплатный тариф с автоматическим спящим режимом.
- **Минусы:** Приложения "засыпают" после 15 минут бездействия, что может нарушить работу ботов.

### 3. PythonAnywhere
- **Плюсы:** Специализированный хостинг для Python, поддерживает фоновые задачи.
- **Минусы:** Ограниченный бесплатный тариф, менее гибкий.

### 4. VPS (DigitalOcean, TimeWeb, Selectel)
- **Плюсы:** Полный контроль, высокая производительность.
- **Минусы:** Требует навыков администрирования, платный.

## Пошаговый план развертывания на Railway.app

### Подготовка репозитория
1. Убедитесь, что проект загружен в GitHub.
2. Проверьте `.gitignore` – он должен исключать `.env`, `data/`, `media/`, `__pycache__/`.
3. Обновите `requirements.txt` при необходимости.

### Создание необходимых файлов
1. **Procfile** (в корне проекта):
```
web: uvicorn web.app:app --host 0.0.0.0 --port $PORT
worker: python -m vk_bot.main
```
2. **runtime.txt** (укажите версию Python):
```
python-3.11
```

### Настройка переменных окружения
В Railway Dashboard → Settings → Variables добавьте:

| Переменная | Значение | Описание |
|------------|----------|----------|
| `BOT_TOKEN` | токен от @BotFather | Токен Telegram бота |
| `VK_TOKEN` | ключ доступа сообщества VK | Токен VK API |
| `VK_GROUP_ID` | числовой ID группы | ID группы VK (без минуса) |
| `SECRET_KEY` | случайная строка | Секретный ключ для сессий |
| `PUBLIC_SITE_URL` | https://ваш-проект.up.railway.app | Публичный URL сайта |
| `DATABASE_PATH` | /data/antidrug.db | Путь к базе данных |
| `MEDIA_PATH` | /media | Путь к медиафайлам |
| `WEB_HOST` | 0.0.0.0 | Хост для веб-сервера |
| `WEB_PORT` | $PORT | Порт (автоматически) |
| `VK_GROUP_PUBLIC_URL` | https://vk.com/ваша_группа | Ссылка на сообщество VK |

### Настройка томов (Volumes) для данных
1. В Railway создайте Volume с именем `data` и подключите его к пути `/data`.
2. Создайте Volume `media` и подключите к `/media`.
3. Обновите `DATABASE_PATH` и `MEDIA_PATH` соответственно.

### Деплой
1. Подключите репозиторий GitHub к Railway.
2. Railway автоматически определит Python-проект и запустит сборку.
3. После успешного деплоя вы получите URL вида `https://ваш-проект.up.railway.app`.

### Запуск ботов
- Процесс `web` запустит веб-сайт автоматически.
- Процесс `worker` запустит VK бота в фоне.
- Для Telegram бота можно добавить второй worker или запустить его в том же процессе (требует модификации кода).

## Альтернатива: Render.com

### Шаги:
1. Создайте новый Web Service, подключив репозиторий.
2. Укажите команду запуска: `uvicorn web.app:app --host 0.0.0.0 --port $PORT`.
3. Создайте Background Worker с командой `python -m vk_bot.main`.
4. Добавьте переменные окружения аналогично Railway.
5. Используйте встроенную базу данных PostgreSQL (требует миграции) или настройте SQLite на ephemeral storage (данные будут теряться при перезапуске).

## Проверка работоспособности

После развертывания:
1. Откройте публичный URL в браузере – должна загрузиться главная страница.
2. Проверьте карту (`/public-map`) – должны отображаться маркеры.
3. Отправьте тестовое сообщение в VK группу – бот должен ответить.
4. Проверьте Telegram бота (если он запущен).

## Мониторинг и логи

- В Railway: вкладка "Logs" показывает логи обоих процессов.
- В Render: вкладка "Logs" для каждого сервиса.
- Используйте логи для отладки ошибок.

## Резервное копирование

- База данных SQLite хранится в Volume, но рекомендуется периодически создавать бэкапы.
- Медиафайлы также хранятся в Volume.

## Дополнительные улучшения

1. **Переход на PostgreSQL** – повысит надёжность и позволит использовать встроенные базы Railway/Render.
2. **Использование облачного хранилища** (S3, Cloud Storage) для медиафайлов.
3. **Настройка домена** – подключите собственный домен в настройках Railway/Render.
4. **Включение HTTPS** – предоставляется автоматически.

## Заключение

Развертывание проекта на Railway.app – наиболее простой и эффективный способ получить работающий сайт и ботов в фоне. Альтернативные платформы также подходят, но могут требовать дополнительной настройки.

Если у вас остались вопросы или нужна помощь с конкретными шагами, обратитесь к документации выбранной платформы или к разработчику.
